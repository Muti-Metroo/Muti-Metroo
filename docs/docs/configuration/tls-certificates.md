# TLS

The `tls` section holds the certificate settings shared by every listener and peer connection. All of it is optional: with no `tls` section, listeners use generated self-signed certificates and peers do not verify certificates. Agent traffic is protected by end-to-end encryption (X25519 and ChaCha20-Poly1305) independently of these settings, so TLS verification is an additional layer, not a requirement.

## Configuration

```yaml
tls:
  ca: "./certs/ca.crt"        # CA for peer verification and mTLS client verification
  cert: "./certs/agent.crt"   # This agent's certificate (listeners and client cert)
  key: "./certs/agent.key"
  # ca_pem, cert_pem, key_pem: inline PEM alternatives to the file paths
  strict: false               # Verify peer certificates against the CA
  mtls: false                 # Require client certificates on listeners
  fingerprint:
    preset: ""                # TLS ClientHello profile for outbound h2/ws dials
```

## Keys

| Key                  | Type   | Default | Description                                                                                                                                       |
| -------------------- | ------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ca`                 | string | `""`    | CA certificate file. Verifies peer certificates when `strict` is on, and client certificates on listeners with mTLS.                             |
| `ca_pem`             | string | `""`    | Inline CA certificate PEM. Takes precedence over `ca`.                                                                                            |
| `cert`               | string | `""`    | Agent certificate file, served by listeners and presented as the client certificate to peers. Generated per listener when unset.                  |
| `key`                | string | `""`    | Private key file for `cert`. Redacted by `config show`.                                                                                           |
| `cert_pem`           | string | `""`    | Inline certificate PEM. Takes precedence over `cert`.                                                                                             |
| `key_pem`            | string | `""`    | Inline private key PEM. Takes precedence over `key`. Redacted by `config show`.                                                                   |
| `strict`             | bool   | `false` | Verify peer certificates against the CA. Requires `ca` or `ca_pem` in this section.                                                              |
| `mtls`               | bool   | `false` | Require and verify client certificates on listeners. Requires `ca` or `ca_pem` in this section.                                                  |
| `fingerprint.preset` | string | `""`    | TLS ClientHello profile for outbound `h2` and `ws` dials. See [ClientHello profiles](#clienthello-profiles).                                     |

A certificate and its key must be set together. Listeners can override `cert`, `key`, and `mtls`; peers can override `ca`, `cert`, `key`, and `strict`. The per-connection keys are listed on [Listeners](/configuration/listeners#keys) and [Peers](/configuration/peers#keys).

## Default behavior

With no certificate configured:

- Each listener generates a self-signed ECDSA certificate when it starts. Generated certificates are not stored and change on every start.
- Peers do not verify the certificate presented by the remote listener.
- Listeners do not ask for client certificates.

All connections use TLS 1.3 (QUIC, HTTP/2, and WebSocket over TLS).

## Certificate requirements

Certificates and CAs used by the mesh must use EC keys. The agent checks this when a listener starts or a peer is dialed and logs an error such as `EC validation failed` for an RSA certificate. Certificates generated by [`muti-metroo cert`](/cli/cert) use P-256 ECDSA keys.

## Strict verification

```yaml
tls:
  ca: "./certs/ca.crt"
  strict: true
```

With `strict: true`, the agent verifies each peer's certificate against the CA and refuses the connection if it does not chain to it. The host name or IP in the peer `address` must appear in the certificate's subject alternative names. A single peer can opt in or out with `tls.strict` on that peer.

## Mutual TLS

```yaml
tls:
  ca: "./certs/ca.crt"
  cert: "./certs/agent.crt"
  key: "./certs/agent.key"
  mtls: true
```

With `mtls: true`, every listener requires the dialing agent to present a client certificate signed by `ca`. Dialing agents present their `cert` and `key` (global, or the per-peer override). A listener can opt out with `tls.mtls: false`. Plaintext WebSocket listeners never use mTLS.

## ClientHello profiles

```yaml
tls:
  fingerprint:
    preset: "chrome"
```

A preset makes outbound `h2` and `ws` dials present a browser-like TLS ClientHello, which some strict proxies and servers expect. It is off by default. QUIC dials and all listeners ignore it.

| Preset                | ClientHello                                    |
| --------------------- | ---------------------------------------------- |
| `chrome`              | Chrome                                         |
| `firefox`             | Firefox                                        |
| `safari`              | Safari                                         |
| `edge`                | Microsoft Edge                                 |
| `ios`                 | iOS Safari                                     |
| `android`             | Android Chrome                                 |
| `random`              | Randomized per connection                      |
| `go`, `disabled`, `""` | Go standard library TLS (no profile)          |

Any other value fails validation.

:::warning
Some web application firewalls treat a browser-like ClientHello followed by non-browser HTTP traffic as a bot signature and reject the connection. If peers behind such a firewall stop connecting after you set a preset, remove it.
:::

## Generating certificates

```bash
muti-metroo cert ca --cn "Mesh CA" -o ./certs
muti-metroo cert agent --cn "agent-1" --dns "agent1.example.com" --ip "192.0.2.10" -o ./certs
```

`cert agent` reads `./certs/ca.crt` and `./certs/ca.key` by default. Flags, validity periods, and expiry checks are documented on [cert CLI](/cli/cert). `muti-metroo run` warns at startup when a configured certificate is close to expiry.

## Examples

### Strict verification with mTLS

```yaml
tls:
  ca: "/etc/muti-metroo/certs/ca.crt"
  cert: "/etc/muti-metroo/certs/agent.crt"
  key: "/etc/muti-metroo/certs/agent.key"
  strict: true
  mtls: true
```

### Certificates from the environment

```yaml
tls:
  ca_pem: "${TLS_CA}"
  cert_pem: "${TLS_CERT}"
  key_pem: "${TLS_KEY}"
  strict: true
```
